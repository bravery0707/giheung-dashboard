# 힐스테이트 기흥 리포트

기흥역세권 · 힐스테이트 기흥(용인시 기흥구 구갈동 660) 한 단지를 보는 정적 대시보드.
의존성 없는 단일 HTML이라 GitHub Pages에 그대로 올리면 됩니다.

첫 화면은 **핵심 숫자와 규제 상태만** 보여주고, 나머지는 탭으로 나눠 두었습니다.

| 탭 | 내용 |
|---|---|
| (첫 화면) | KB 일반가와 하위–상위 밴드, 최근 실거래, 전세가율, 매물 수, 규제 알림 한 줄 |
| 개요 | 평형별 시세 미니 차트, 최근 실거래 6건, 단지 요약, 필요 자기자본, 계약 전 체크리스트 |
| 평형·시세 | 평형별 매매/전세 막대, 전세가율, 7개 타입 976세대 구성 |
| 실거래 | 월별 평균·최저–최고 밴드 + 거래량, 정렬·검색·신고가 판정 테이블, CSV 내보내기 |
| 매물 | 네이버 부동산 파일 업로드, 호가 분포·층대·동별 분석, 호가 vs 실거래 갭, 중개소 묶음 |
| 계산기 | 취득세(중과 포함)·중개보수·등기비용·LTV 한도·보유세·수익률 |
| 입지 | 기흥역 반경 개념도, 개발 호재 타임라인, 1지구 5개 단지 비교 |
| 데이터 | 국토부 연결, 갱신 방법, 출처 |

라이트/다크 자동 대응, 모바일 우선 반응형입니다.

## 실거래가 — 국토교통부 (자동)

### 어떤 API를 신청해야 하나

**인증키는 계정당 하나**입니다. 이미 발급받았다면 새 키를 또 받을 필요 없이,
아래 API에 **활용신청만 추가**하면 같은 키로 호출됩니다(자동 승인, 보통 몇 분).

| API | 필요도 | 없으면 |
|---|---|---|
| [아파트 매매 실거래가 자료](https://www.data.go.kr/data/15126469/openapi.do) (15126469) | 필수 | 매매 차트·테이블의 기본 소스 |
| [아파트 전월세 실거래가 자료](https://www.data.go.kr/data/15126474/openapi.do) (15126474) | 권장 | 전세·월세 추이와 실거래 기준 전세가율 |
| [아파트 매매 실거래가 상세 자료](https://www.data.go.kr/data/15126468/openapi.do) (15126468) | 권장 | 동(棟)·등기일자 — 매물의 동별 비교 |

`scripts/update.mjs`는 **상세 자료 → 기본 자료** 순으로 시도하고, 활용신청이 안 된 API는
자동으로 건너뛴 뒤 어떤 소스를 썼는지 로그와 `data/transactions.json`의
`apisUsed` / `apisSkipped`에 남깁니다.

상세 자료가 붙으면 실거래에 **동(棟)** 정보가 들어와, 실거래 테이블에 동 열이 생기고
네이버 매물의 동별 호가와 직접 비교할 수 있습니다.

### 0) 먼저 키가 제대로 먹는지 확인

```bash
export DATA_GO_KR_KEY="일반 인증키(Decoding)"     # Windows PowerShell: $env:DATA_GO_KR_KEY="..."
node scripts/update.mjs --check
```

```
인증키 점검 — 202609 기준, 지역코드 41463

  ✅ 아파트 매매 실거래가 상세 자료  —  202609 전체 128건 / 힐스테이트기흥 2건
  ✅ 아파트 매매 실거래가 자료      —  202609 전체 128건 / 힐스테이트기흥 2건
  ✅ 아파트 전월세 실거래가 자료    —  202609 전체 210건 / 힐스테이트기흥 3건
```

3개 모두 ✅ 가 아니면 그 API만 활용신청 상태를 다시 확인하세요.
신청 직후에는 반영까지 몇 분에서 최대 1시간이 걸릴 수 있습니다.

> 포털은 **Encoding 키**와 **Decoding 키**를 함께 줍니다. 스크립트가 쿼리스트링을 다시 인코딩하므로
> Encoding 키를 그대로 넣으면 `%252B`처럼 이중 인코딩되어 인증이 실패합니다.
> 스크립트가 `%2B` 같은 패턴을 감지하면 자동으로 한 번 디코딩하지만, 되도록 **Decoding 키**를 쓰세요.

### 1) 전체 수집

```bash
node scripts/update.mjs --months 36
```

`data/transactions.json`이 만들어집니다. 어떤 API를 썼는지는 `apisUsed` / `apisSkipped`에 남습니다.

### 2) GitHub Actions 매일 갱신 (권장)

1. `Settings → Secrets and variables → Actions → New repository secret`
   - Name `DATA_GO_KR_KEY` / Secret **일반 인증키(Decoding)**
2. 푸시하면 매일 KST 05:00에 `data/transactions.json`이 갱신되고 자동 커밋됩니다.
   `Actions → 실거래 데이터 갱신 → Run workflow`로 즉시 실행할 수도 있습니다.

키는 시크릿에만 들어가고 저장소 파일이나 페이지에는 남지 않습니다.

### CSV 업로드

[실거래가 공개시스템](https://rt.molit.go.kr)에서 받은 CSV를 **데이터** 탭에 끌어다 놓으면 즉시 반영됩니다.

> `apis.data.go.kr`은 CORS 헤더를 주지 않아 정적 페이지에서 직접 `fetch`할 수 없습니다.
> 수집은 Node(Actions/로컬), 페이지는 결과 JSON만 읽는 구조라 페이지에 키를 심지 않아도 됩니다.

## 매물 — 네이버 부동산 (파일 업로드)

네이버 부동산은 공개 API가 없고 이용약관상 자동 수집이 금지되어 있어, 매물만 수동 업로드입니다.
**매물** 탭에 내려받은 `.xlsx` 또는 `.csv`를 끌어다 놓거나, 시트를 복사해 붙여넣으면 됩니다.

기대하는 열(순서 무관):

```
동 | 매/전 | 가격 | 면적 | 층 | 향 | 정보 | 중개소 | 에이전트 | 등록일자
```

- `↳`로 시작하는 행은 **같은 물건을 올린 다른 중개소**로 묶습니다. 중개소 중복 게시 때문에
  매물 수가 부풀려지는 문제를 없애고, 고유 물건 수와 게시 수를 따로 보여줍니다.
- 가격: `13억`, `11억 5,000`, `1억 5,000/230`(월세), `11억 5,000 ~12억 5,000`(범위) 모두 인식.
- 층: `고/49층` 표기와 `39/49층` 실층수 둘 다 처리.
- 면적: `120A-1/84m²`에서 타입과 전용면적을 분리.

엑셀은 **외부 라이브러리 없이** 브라우저 안에서 해제해 읽습니다
(ZIP 파싱 + `DecompressionStream`). CDN 의존성이 없어 오프라인·사내망에서도 동작하고,
`DecompressionStream`이 없는 구형 브라우저에서는 CSV로 저장해 올리면 됩니다.

매물 탭에서 볼 수 있는 것:

- 고유 매물 수 / 중개소 게시 수 / 물건당 중개소 수
- 매매 최저·중위·최고 호가, 최근 7일 신규
- **호가 vs 실거래 갭** — 중위 호가가 최근 실거래 평균 대비 몇 % 높은지
- 타입별 호가 분포(점 하나 = 물건 하나) + 실거래 평균 참조선
- 층대별 중위 호가, 동별 매물 수, 일자별 중개소 게시 추이
- 거래·타입·동·층 필터, 중개소 메모에서 뽑은 키워드 칩 필터, 즐겨찾기
- 행을 펼치면 그 물건을 올린 중개소 목록과 각 중개소의 소개 문구

**JSON** 버튼으로 내보내 `data/listings.json`에 커밋하면 다른 기기에서도 같은 매물이 보입니다.

## 데이터 구조

`data/transactions.json`

```json
{
  "updated": "2026-09-01 05:00:12 UTC",
  "apisUsed": ["아파트 매매 실거래가 자료"],
  "apisSkipped": ["아파트 전월세 실거래가 자료"],
  "count": 412,
  "transactions": [
    { "date": "2026-06-30", "deal": "매매", "area": 84.95, "py": 36,
      "floor": 47, "amount": 118000, "src": "국토부 API" }
  ]
}
```

- `amount` 단위는 **만원**. 전월세는 보증금이 `amount`, 월세가 `rent`.
- `py`가 없으면 전용면적에서 산출(**79㎡ 미만 31평 / 90㎡ 미만 36평 / 그 이상 41평**).
- 해제된 거래(`cdealType = O`)는 수집 단계에서 제외.

## 검증된 값과 추정치

확인값: 세대수 976, 타입별 세대수, KB시세(2026-08-21), 규제 지정 일자, 주변 단지 세대수,
그리고 **타입별 전용면적**(2026-09-01 네이버 부동산 매물 목록 표기 — 104형 72㎡ · 120·121형 84㎡ · 137형 95㎡).

> 초기 버전에서 104형을 전용 84.95㎡로 잡았던 것은 오류였습니다. 매물 목록으로 바로잡았고,
> 평형 분류 기준도 전용 79㎡ / 90㎡로 수정했습니다.

추정치: 소수점 단위 전용면적, 시뮬레이터의 공시가격(시세×69%)과 보유세.
국토부 실거래를 연결하면 신고된 전용면적으로 교정됩니다.
