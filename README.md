# 힐스테이트 기흥 데이터랩

힐스테이트 기흥 한 단지의 국토교통부 실거래와 네이버 부동산 매물 스냅샷을 함께 보는 GitHub Pages 대시보드입니다.

## 화면 구성

- **요약** — 최근 실거래, 현재 호가, 호가-실거래 갭, 최근 변동 신호
- **실거래** — 면적·기간·높이별 반응형 차트와 테이블
- **매물 현황** — 거래·면적·높이 필터, 호가 분포, 중복 중개소 상세
- **매물 추이** — 조사일별 고유 매물 수와 중간 호가
- **매물 변동** — 스냅샷 사이 신규·소멸 후보·가격변동, 지속 소멸 후보

기본 필터는 `매매 · 84㎡ · 36개월 · 전체 높이`입니다.

## 실거래 자동 갱신

`.github/workflows/update-data.yml`이 매일 KST 05:00에 실행됩니다. 저장소 Secret은 하나만 필요합니다.

```text
DATA_GO_KR_KEY = 공공데이터포털 일반 인증키(Decoding)
```

활용신청 API:

1. 아파트 매매 실거래가 상세 자료 `15126468`
2. 아파트 매매 실거래가 자료 `15126469`
3. 아파트 전월세 실거래가 자료 `15126474`

페이지의 **최신 데이터** 버튼은 인증키를 브라우저에 노출하거나 OpenAPI를 직접 부르지 않습니다. GitHub Actions가 만들어 둔 JSON을 캐시 없이 다시 읽습니다.

## 매물 스냅샷 갱신

1. Edge + Tampermonkey로 네이버 부동산의 힐스테이트 기흥 엑셀을 내려받습니다.
2. 저장소의 `incoming` 폴더에 `listings.xlsx`라는 이름으로 업로드합니다.
3. **매물 엑셀 반영** Action이 자동으로 실행됩니다.

Action은 엑셀을 `data/listings.json`으로 변환하고 `data/listing-history.json`에 날짜별 변동을 누적합니다. 같은 날짜 파일은 해당 날짜를 교체합니다. 일별 변동을 보려면 하루 한 번 스냅샷을 올려야 합니다.

> Edge/Tampermonkey는 PC와 브라우저가 실행 중일 때만 동작합니다. GitHub Actions에서 네이버 내부 API를 직접 무인 호출하는 방식은 사이트 변경·인증·이용조건 문제 때문에 포함하지 않았습니다.

## 변동 판정 기준

- 동일 매물 매칭: 거래 종류, 동, 타입, 면적, 실제 층/높이, 향, 겹치는 중개소를 종합 비교
- 신규: 이전 스냅샷에 대응되는 매물이 없음
- 소멸 후보: 이번 스냅샷에 대응되는 매물이 없음
- 가격변동: 동일 추적 ID의 호가가 달라짐
- 지속 소멸 후보: 소멸 후 한 번 이상의 후속 스냅샷에도 재등장하지 않음

매물 소멸은 거래 완료를 뜻하지 않습니다. 광고 만료, 중개사 철회, 재등록 가능성이 있으므로 국토부 신고자료·중개사 확인과 교차 검증해야 합니다.

## 로컬 실행

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다.
