# 네이버 화면 수집기

## 현재 검증 상태

2026-09-06 힐스테이트기흥 네이버 화면의 대표 매물 총계, 묶음 중개사 수, 펼친 광고의 상세 링크를 확인하여 DOM 수집기를 구현했다. 별도 Chrome 프로필의 실제 자동 수집 1회는 첫 화면을 여는 동안 `BUDGET`으로 중단됐다. 총 요청 300건 또는 문서·XHR·fetch 100건 중 어느 상한이 먼저 걸렸는지는 첫 실행 로그에 남지 않아 확정하지 않는다. 이후 요청 종류별 진단을 추가했지만 네이버에 재요청하여 확인하지 않았다.

기존 정상 자료와 이력은 보존했고 2026-09-06 재실행은 영구 날짜 기록으로 차단된다. 상한을 올리거나 날짜 기록·저장 경로를 바꾸어 재시도하지 않았다. 현재 예약 수집은 실행 중이 아니다. 실제 완전 수집 성공, 무인 운영, 14일 운영 성공을 의미하지 않는다.

로컬 검증: 자동 테스트 42개 통과. 모든 요청을 가상 HTML로 응답하는 실제 Chrome 통합 검사에서 묶음 펼치기 → 광고 ID·원본 표시 건수·가격 검증 → 비공개 저장이 통과했다. 이 검사는 실제 네이버 요청을 보내지 않는다.

## 처리 범위

- 한 단지의 전체 거래유형·전체 면적·전체 동 화면만 읽는다. 단기 매물이 있거나 0건·총계 불일치·지원하지 않는 표시 형식이면 실패한다.
- 목록 제목의 대표 건수와 거래별 버튼 총계를 별도로 읽는다. 각 묶음의 ‘중개사 N곳’과 추출된 광고 ID 수를 대조한다. 읽은 ID 개수를 원본 예상 총계로 복사하지 않는다.
- 묶음은 순서대로 펼치며 개별 매물 상세 페이지로 이동하지 않는다. 스크롤이 필요하면 최대 10회다. 목록 수가 맞지 않거나 그룹 광고가 모두 나오지 않으면 실패한다.
- 수집 전후 목록의 순서·가격·속성·묶음 수가 바뀌면 반영하지 않는다. 개별 광고 최저·최고 호가와 대표 가격 범위도 대조한다. 월세의 복잡한 보증금·월세 범위는 추정하지 않고 실패한다.
- 면적은 정확한 전용면적, 금액은 만원이다. 실제 층이 공개되지 않으면 저·중·고만 기록한다. 광고 확인일과 관측 시각은 구분한다.
- 광고 ID, 동·면적·층·방향·금액·확인일을 저장한다. 전화번호·중개사 설명·사진·로그인 정보는 추출하지 않는다.
- 첫 브라우저 성공 관측 시 기존 엑셀 이력은 `.private/listing-data/history-before-naver-날짜.json`으로 보존하고 새 관측 기준점을 만든다. 서로 다른 수집 기준을 바로 비교해 전부 신규·소멸로 표시하지 않는다. 자동 수집 두 번째 정상 관측부터 변화 분석이 시작된다.

## 실행 환경

Node.js 22 이상과 Chrome이 필요하다. 저장소에서 `pnpm install --frozen-lockfile --ignore-scripts`로 잠금 파일에 지정된 Playwright를 설치한다. 이 PC에서 설치와 통합 검사를 확인했다. 이 PC의 번들 런타임을 이용할 때는 `NAVER_PLAYWRIGHT_MODULE`을 설치된 `playwright/index.mjs` 절대 경로로 지정할 수도 있다.

Chrome 사용자 프로필과 분리된 `.private/naver-browser-profile`을 사용한다. 기존 Chrome 쿠키·토큰·프로필을 복사하지 않는다. 브라우저 창은 실행 중 나타나고 종료 시 닫힌다.

개인 설정은 `.private/naver-config.json`이다. 아래 날짜는 예시이며 시험 기간을 임의로 초기화하지 않는다.

```json
{
  "enabled": true,
  "mode": "naver-browser",
  "privateUseAcknowledged": true,
  "trial": { "startDate": "2026-09-06", "days": 14 }
}
```

`privateUseAcknowledged`는 사용자의 개인 분석 설정 확인이며 네이버의 허가를 나타내지 않는다. 낮은 빈도와 UI 방식만으로 약관 허용이나 탐지되지 않음을 보장하지 않는다.

```sh
node scripts/collect-naver.mjs
node scripts/private-dashboard.mjs
```

**현재는 실제 성공 검증 전이므로 예약 명령을 활성화하지 않는다.** 실제 전체 수집과 같은 시점 화면 대조가 성공하면 `node scripts/private-dashboard.mjs --schedule-naver`로 한국시간 21:10 이후 하루 1회 연결할 수 있다. PC·프로그램이 켜져 있어야 하며 날짜 누락을 소급 생성하지 않는다.

## 제한과 진단

브라우저 실행 전에 기존 피드와 공유하는 파일 잠금·일일 요청 기록을 확보한다. 하루 1회는 HTTP 1건을 의미하지 않는다. 총 브라우저 요청 시도 300건, 문서·XHR·fetch 100건, 화면 조작 45회, 4분, 조작 간격 2초를 상한으로 둔다. 초과 요청은 보내지 않는다. 이미지·미디어·폰트·WebSocket·서비스 워커는 생략한다. 브라우저 외부 프로세스의 트래픽까지 측정하는 방화벽은 아니다.

네이버의 401·403·429, 로그인 이동, CAPTCHA·보안 확인은 지속 중지한다. 실패는 같은 날 재시도하지 않으며 정상 자료를 덮어쓰지 않는다. 접근 거부는 날짜가 바뀌어도 수동 재개 전까지 멈춘다. 기존 `collect-listings.mjs --resume --reason "해결 내용"`은 중지 상태만 해제하며 일일 할당량을 돌려주지 않는다.

진단은 `.private/listing-data/naver-last-attempt.json`(실패)과 `naver-audit.json`(성공)에 저장한다. 요청 종류별 시도 수·조작 수·원본 총계·검증 결과만 남기며 URL, 응답 본문, 토큰을 기록하지 않는다. 요청 시도 수는 차단된 마지막 시도를 포함할 수 있어 실제 전송 건수와 같지 않다.

다음 실제 시험에서는 진단으로 초기 정적 파일과 문서·데이터 요청 중 어느 쪽이 상한을 소진하는지 먼저 구분해야 한다. 화면에 불필요한 요청을 줄이는 방안을 확인한 후 같은 기준으로 완전 수집을 검증한다. 원인 확인 없이 상한을 계속 늘리는 방식으로 운영하지 않는다.

## 로컬 테스트

```sh
node --test tests/*.test.mjs
node tests/naver-browser-check.mjs
node scripts/build-public.mjs
```

두 번째 명령은 설치된 Chrome과 Playwright가 필요하고 가상 응답만 사용한다. GitHub 기본 CI는 의존성이 필요 없는 첫 번째 검사와 공개 빌드를 수행한다. 실제 매물·프로필·설정은 GitHub와 공개 빌드에 포함되지 않는다.
