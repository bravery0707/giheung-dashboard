# 매물 자동 갱신과 14일 시험 운영

2026-09-06 기준으로 비공개 로컬 저장, 요청 제한, 접근 거부 시 지속 중지와 공개 배포물 검사를 구현했다. 별도로 [네이버 브라우저 수집기](naver-browser.md)를 추가했으며 실제 첫 시험은 초기 요청 상한에서 중단됐다. 아래 문서는 기존 JSON 피드 연결부의 계약과 설정이다. 네이버 문의 메일을 보내는 절차는 진행하지 않는다. 개인 분석과 낮은 요청 빈도만으로 적법성이나 탐지되지 않음을 보장하는 설계는 아니다.

## 수집 경로 확인 결과

- [네이버 오픈 API 목록](https://developers.naver.com/products/intro/plan/plan.md)에는 단지별 현재 매물 조회 API가 없다.
- [네이버 접근 정책](https://policy.naver.com/rules/disclaimer.html)은 자동 수집에 대해 명시적 허용·사전 승낙 또는 허용된 API/탐색 범위 등의 예외를 안내한다.
- [네이버페이 부동산](https://land.naver.com/) 하단은 게시 정보의 무단 복제·배포·전송을 제한한다고 명시한다. 이 페이지에는 기존 PC 서비스가 2026년 말 종료될 예정이라는 안내도 있다.
- 수집 허용과 공개 대시보드 재배포 허용은 각각 확인해야 한다. 단순히 저빈도로 실행하거나 중개사 한 곳의 승낙을 얻는 것만으로 네이버 전체 매물의 수집 권한이 확보된 것으로 보지 않는다.

기존 피드 연결부는 제공처의 JSON을 받아 아래 계약을 검증한다. 별도 브라우저 수집기는 화면 DOM만 읽으며 비공개 API 직접 호출, 인증 토큰 추출, CAPTCHA 해결이나 우회 프록시는 사용하지 않는다.

## 데이터 계약

자동 피드는 힐스테이트기흥 아파트의 매매·전세·월세, 전체 면적을 한 번에 수집한 JSON이어야 한다. 매물 종류나 면적 필터를 바꾸어 수집하면 기존 전체 스냅샷과 비교하지 않는다. 수집기는 모든 페이지와 중복 광고를 확인한 후에만 `quality.complete=true`를 기록해야 한다. 단순히 읽어 온 개수를 예상 총계로 복사하면 전체 수집 검증이 되지 않는다.

```json
{
  "schemaVersion": 2,
  "complex": "힐스테이트기흥",
  "scope": "hillstate-giheung:APT:all-deals:all-areas",
  "source": "approved-provider-id",
  "date": "2026-09-06",
  "startedAt": "2026-09-06T21:09:00+09:00",
  "capturedAt": "2026-09-06T21:10:00+09:00",
  "quality": {
    "complete": true,
    "expectedUnique": 1,
    "expectedPostings": 1,
    "expectedPages": 1,
    "pagesFetched": 1
  },
  "listings": [{
    "sourceIds": ["example-advertisement-id"],
    "dong": "203",
    "deal": "매매",
    "type": "120A",
    "area": 84,
    "floor": 20,
    "band": "중",
    "face": "남동향",
    "price": 130000,
    "priceMax": null,
    "rent": 0,
    "count": 1,
    "agents": [{ "name": "예시 중개소" }]
  }]
}
```

위 JSON은 형식 설명용 가상 매물이며 실제 관측값이 아니다. 가격과 월세는 만원, 면적은 전용면적 ㎡다. 원본의 정확한 면적 수치를 보존한다. 실제 층이 없으면 `floor=null`로 두고 공개된 저·중·고 구분만 기록한다. `sourceIds`는 원본 광고 ID 전체 목록이고 `count`와 개수가 같아야 한다. 대표 매물의 묶음이 실제 한 주택임을 보장하는 것은 아니다. 자료에 없는 호수를 추정해 만들지 않는다.

수집 시각은 등록일·확인일과 별개다. 자동 피드는 한국시간 당일 수집, 최근 6시간 이내, 직전 수집보다 새로운 결과만 받는다. 확인 시각과 수집 시각이 다르면 새 스냅샷을 등록일로 덮어쓰지 않는다.

## 로컬 설정과 활성화

실제 JSON 피드 또는 이를 만드는 어댑터가 먼저 필요하다. 설정만 채운다고 네이버 수집 기능이 생기지 않는다. 제공처의 이용 조건이나 명시적으로 허용된 인터페이스 등 확인된 수집 근거를 `permission.reference`에 기록한다. 개인 이용 목적 자체를 수집 허용으로 기록하지 않는다. 문의 메일만을 유일한 확인 방법으로 요구하지 않으며, 공개 재배포 권한은 비공개 수집의 활성화 조건에서 제외했다.

1. `config/listing-source.json`을 `.private/source.json`으로 복사한다. `source`, `allowedOrigin`, `permission.collection`, `permission.reference`, 실제 `trial.startDate`를 채운다. 시험 기간은 1~14일이다.
2. PC 환경변수 `LISTING_CONFIG`를 이 비공개 설정 파일의 절대 경로로, `LISTING_FEED_URL`을 실제 HTTPS JSON 주소로 지정한다. 필요한 경우 `LISTING_FEED_TOKEN`을 사용한다. GitHub Secrets나 공개 파일에 넣을 필요가 없다.
3. `node scripts/collect-listings.mjs --check`로 설정을 확인한다. 이 명령은 네트워크 요청을 보내지 않는다.
4. `enabled=true`인 유효한 설정에서 `node scripts/collect-listings.mjs`를 실행하면 당일 요청 1회를 사용한다. 정상 결과를 원본 총계와 대조한 뒤 `node scripts/private-dashboard.mjs --schedule`을 실행한다.
5. 예약은 한국시간 21:10 이후 처음 확인하는 시점에 실행한다. 늦게 시작하면 그날 1회 실행하고, 지나간 날짜를 소급 수집하지 않는다. PC와 프로그램이 켜져 있어야 한다. 정전·절전 중 정시 실행을 보장하지 않는다.
6. 시험 기간 종료 후에는 요청을 보내지 않는다. 운영 결과 확인 없이 자동 연장하지 않는다.

## 요청 제한과 수동 재개

- 하나의 저장 폴더에 파일 잠금을 걸어 동시 수집과 가져오기를 막는다. 요청 직전에 한국시간 날짜를 `request-state.json`에 기록하므로 실패·시간 초과·프로그램 재시작에도 같은 날 요청이 추가되지 않는다. 상태 파일이나 저장 폴더를 지워 제한을 초기화하지 않는다.
- 피드 GET은 하루 최대 1회, 응답은 5 MiB, 요청과 본문 읽기는 최대 30초다. 제공처 내부 수집량을 제한하는 것은 아니므로 향후 네이버 어댑터를 만들면 그 어댑터 자체에도 페이지 수·간격·요청 총량 제한을 별도로 적용해야 한다.
- 401·403·429·리디렉션 또는 비JSON/HTML 응답은 지속 중지한다. Retry-After가 짧아도 자동 재시도하지 않는다. CAPTCHA 자동 해결, IP 교체, 프록시 회전, 인증 우회는 구현하지 않았다.
- 접근 문제를 해결한 뒤 `node scripts/collect-listings.mjs --resume --reason "해결한 내용"`으로 재개할 수 있다. 일일 요청 횟수와 시험 기간은 초기화하지 않는다.
- 강제 종료로 `collection.lock`이 남으면 자동으로 삭제하지 않는다. 파일에 기록된 PID의 작업이 끝났는지 확인하고 백업한 뒤 잠금 파일만 수동 제거한다. `request-state.json`은 유지한다. 이는 수집량 제한을 우선한 복구 방식이다.
- 상태 파일이 깨졌거나 형식을 확인할 수 없으면 요청을 보내지 않는다. 복구할 때도 이전 정상 자료와 요청 기록을 보존한다.

## 판정과 실패 처리

- 원본 광고 ID가 겹치고 필수 속성이 일치하면 연결한다. 과거에 관측한 ID가 다시 나오면 신규와 구분해 재등장으로 기록한다.
- 기존 엑셀에는 광고 ID가 없다. 이 경우 동·타입·면적·층·방향과 중개소 중복을 보수적으로 비교하고, 후보가 하나일 때만 속성으로 추정해 연결한다. 애매한 경우는 새 추적으로 남기고 ‘동일성 미확인’을 표시한다.
- 같은 출처의 광고 ID가 모두 달라지면 새 광고로 남긴다. 실제 같은 집의 재등록인지 자동으로 확정하지 않는다. 제공처가 검증된 주택 식별자를 제공하면 추후 연결 규칙을 보완할 수 있다.
- 그룹 분할·병합으로 여러 대응이 생기면 임의로 하나를 선택하지 않는다. 신규·소멸 후보 수에는 이런 불확실성이 포함될 수 있다.
- 지속 소멸은 마지막 관측 뒤 정상 조사에서 2회 이상 미관측인 매물이다. 마지막 관측일과 첫 미관측 조사일을 따로 표시한다. 누락된 날짜를 자동으로 미관측 1회로 보간하지 않는다. 재등장 후에는 횟수를 다시 센다.
- 3·7·14일 필터는 마지막 관측 이후 달력상 경과일이다. 매일 정상 수집되었다는 의미는 아니므로 미관측 조사 횟수를 함께 본다.
- 페이지 누락, 총계 불일치, 중복 ID, 형식 오류, 오래된 응답, 원본 ID 누락은 전체 스냅샷을 거절한다.
- 직전 정상 조사보다 대표 매물이 절반 미만으로 감소하면 확인 대상으로 보류한다. 완전한 0건도 자동 소멸 처리하지 않는다. 원본 전체 건수 확인 후 수동 실행에서만 `--accept-count-drop`으로 반영한다.
- 실패하면 이전 매물·이력을 유지하고 `collection-status.json`에 실패 상태만 저장한다. 원본 응답·인증정보·제공처 오류 본문은 공개 상태 파일에 쓰지 않는다.
- 숫자·속성·광고 ID·전화번호를 제거한 중개소명은 비공개 분석 파일에만 보존한다. 설명문·연락처·쿠키·인증 토큰은 매물 분석 데이터에 저장하지 않는다.
- 이력 파일은 임의의 180회 제한으로 잘라내지 않는다. 공급 계약의 보관기간이 결정되면 그에 맞춘 보관·삭제 정책을 설정한다.

## 배포

개인 화면은 `node scripts/private-dashboard.mjs`로 실행한다. `127.0.0.1`에만 바인딩하고 Host·Origin을 검사하며, 지정된 정적 파일과 분석 JSON만 응답한다. 임의 폴더 열람·외부 Origin·다른 Host·쓰기 요청은 거절한다. 화면을 열거나 새로고침하는 것으로 수집 요청은 발생하지 않는다. 로컬 파일을 암호화하는 기능은 아니므로 PC와 백업의 접근 권한은 별도다.

Pages에는 `node scripts/build-public.mjs`가 만든 `_site`만 배포한다. 공개 `data/listings.json`, `listing-history.json`, `collection-status.json`은 비공개 안내를 위한 빈 값이다. 매물 자료를 0건으로 해석하지 않고 비공개로 표시한다. 공개 빌드의 파일 허용 목록에는 실거래 JSON만 실제 데이터로 들어간다. 원본이 공개 입력 파일이나 `incoming`에 섞이면 빌드를 실패시킨다.

GitHub의 매물 수집 및 엑셀 업로드 workflow는 읽기 전용 검사로 전환했다. 원본을 커밋하거나 Actions artifact로 전송하지 않는다. 국토교통부 실거래 갱신과 Pages 배포는 유지한다. 현재 파일을 제거해도 과거 Git 커밋·PR·캐시·사본에 이미 공개된 자료는 남는다. 기존 공개 이력 삭제는 별도 작업이다.

## 14일 시험에서 확인할 것

실제 시작일은 데이터 이용 확인 후 정한다. 인공 데이터 회귀 검사를 실제 시험 수집 실적으로 기록하지 않는다.

| 점검 | 기준 |
|---|---|
| 최초 수집 | 제공처 전체 총계와 대표·광고 건수 일치, 모든 페이지 확인 |
| 매일 수집 | 예약 시각과 실제 수집 시각 기록, 전체 범위 유지 |
| 정확도 | 최초일, 변동 발생일, 종료일에 표본 광고 ID·금액·층·중복 묶음을 원본과 대조 |
| 변동 | 신규·가격 상하한·월세·소멸·재등장 사례 확인. 실제 발생하지 않은 사례는 별도 시험 데이터로 검증 |
| 장애 | 누락 응답과 인증 실패를 주입했을 때 데이터 유지·실패 표시 확인 |
| 중복 매칭 | 신규/소멸로 잘못 잡힌 광고 교체·그룹 분할 사례를 따로 기록 |
| 최종 판단 | 14일 동안의 정상 수집 비율과 누락 원인, 유지 비용·허용 조건을 보고 운영 여부 결정 |

실거래 신고와 매물은 확정 연결하지 않는다. 매물 소멸은 거래 완료를 의미하지 않는다.
