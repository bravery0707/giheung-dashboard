# 매물 자동 갱신과 14일 시험 운영

2026-09-06 기준으로 자동 수집 프로그램의 연결부와 검증·이력·배포 기능을 준비했다. 네이버의 매물 데이터를 가져오는 허가된 API 또는 피드는 아직 확보하지 않았다. 현재 설정은 비활성화되어 있으며 실제 네이버 무인 수집 시험을 시작한 상태가 아니다.

## 수집 경로 확인 결과

- [네이버 오픈 API 목록](https://developers.naver.com/products/intro/plan/plan.md)에는 단지별 현재 매물 조회 API가 없다.
- [네이버 접근 정책](https://policy.naver.com/rules/disclaimer.html)은 자동 수집에 대해 명시적 허용·사전 승낙 또는 허용된 API/탐색 범위 등의 예외를 안내한다.
- [네이버페이 부동산](https://land.naver.com/) 하단은 게시 정보의 무단 복제·배포·전송을 제한한다고 명시한다. 이 페이지에는 기존 PC 서비스가 2026년 말 종료될 예정이라는 안내도 있다.
- [네이버파이낸셜](https://www.naverfincorp.com/main) 하단의 ‘제휴문의’ 팝업에는 금융 제휴문의 이메일이 안내되어 있다. 부동산 데이터 승인 전용 창구는 확인되지 않았으므로 우선 담당 부서 연결을 요청하는 경로로만 사용한다. 부동산 데이터 제공 계약이나 개인 연구용 승인이 실제로 제공되는지는 회신이 필요하다.
- 수집 허용과 공개 대시보드 재배포 허용은 각각 확인해야 한다. 단순히 저빈도로 실행하거나 중개사 한 곳의 승낙을 얻는 것만으로 네이버 전체 매물의 수집 권한이 확보된 것으로 보지 않는다.

현재 코드에는 네이버 비공개 엔드포인트, 인증 토큰 추출, CAPTCHA 처리, 우회 프록시 또는 브라우저 스크래퍼를 넣지 않았다. 승인된 제공처의 JSON 피드를 받아 아래 계약을 검증하는 연결부다. 실제 제공처의 규격이 다르면 그 규격에 맞춘 어댑터를 추가하고 검증해야 한다.

## 데이터 계약

자동 피드는 힐스테이트기흥 아파트의 매매·전세·월세, 전체 면적을 한 번에 수집한 JSON이어야 한다. 매물 종류나 면적 필터를 바꾸어 수집하면 기존 전체 스냅샷과 비교하지 않는다. 수집기는 모든 페이지와 중복 광고를 확인한 후에만 `quality.complete=true`를 기록해야 한다. 단순히 읽어 온 개수를 예상 총계로 복사하면 전체 수집 검증이 되지 않는다.

```json
{
  "schemaVersion": 2,
  "complex": "힐스테이트기흥",
  "scope": "hillstate-giheung:APT:all-deals:all-areas",
  "source": "approved-provider-id",
  "date": "2026-09-06",
  "startedAt": "2026-09-06T21:09:00+09:00",
  "capturedAt": "2026-09-06T21:10:00+09:00",
  "quality": {
    "complete": true,
    "expectedUnique": 1,
    "expectedPostings": 1,
    "expectedPages": 1,
    "pagesFetched": 1
  },
  "listings": [{
    "sourceIds": ["example-advertisement-id"],
    "dong": "203",
    "deal": "매매",
    "type": "120A",
    "area": 84,
    "floor": 20,
    "band": "중",
    "face": "남동향",
    "price": 130000,
    "priceMax": null,
    "rent": 0,
    "count": 1,
    "agents": [{ "name": "예시 중개소" }]
  }]
}
```

위 JSON은 형식 설명용 가상 매물이며 실제 관측값이 아니다. 가격과 월세는 만원, 면적은 전용면적 ㎡다. 원본의 정확한 면적 수치를 보존한다. 실제 층이 없으면 `floor=null`로 두고 공개된 저·중·고 구분만 기록한다. `sourceIds`는 원본 광고 ID 전체 목록이고 `count`와 개수가 같아야 한다. 대표 매물의 묶음이 실제 한 주택임을 보장하는 것은 아니다. 자료에 없는 호수를 추정해 만들지 않는다.

수집 시각은 등록일·확인일과 별개다. 자동 피드는 한국시간 당일 수집, 최근 6시간 이내, 직전 수집보다 새로운 결과만 받는다. 확인 시각과 수집 시각이 다르면 새 스냅샷을 등록일로 덮어쓰지 않는다.

## 활성화 순서

1. 제공처에서 수집, 보관, 공개할 필드, 공개 기간, 집계 및 재배포 가능 여부와 요청 제한을 회신받는다. 원문 회신은 비공개 보관하고 공개 설정에는 비밀정보 없는 승인 식별자만 남긴다.
2. 제공처 규격에 맞춘 어댑터가 위 JSON을 출력하게 연결한다. 허용된 주소의 HTTPS GET만 사용한다. 리다이렉트를 따라 인증정보를 전달하지 않는다.
3. `config/listing-source.json`에 `source`, `allowedOrigin`, 허용 범위와 근거 식별자를 채우고 시험 시작일을 정한다. `trial.days`는 최대 14일이다.
4. 저장소 Secrets에 `LISTING_FEED_URL`, 필요 시 `LISTING_FEED_TOKEN`을 저장한다. 토큰을 HTML, JSON 데이터, URL 또는 공개 설정에 넣지 않는다.
5. 저장소 변수 `LISTINGS_AUTOMATION_ENABLED=true`와 설정의 `enabled=true`를 모두 지정한다. 기본값은 비활성화다. 허용 확인 전에는 활성화하지 않는다.
6. Settings → Pages → Source를 **GitHub Actions**로 설정하고, 수동 실행으로 전체 수집과 배포를 한 번 확인한다.
7. 자동 실행은 매일 한국시간 21:10에 예약한다. GitHub 실행 지연에 대비해 실제 수집 시각을 비교한다. 정확한 시각의 수집을 제공처가 지원하는지도 확인한다.
8. 14일 시험 기간이 끝나면 수집 요청이 중단된다. 결과를 검토한 후 운영 기간과 일정을 변경한다. 자동으로 유료 서비스를 신청하거나 시험 기간을 연장하지 않는다.

네이버의 허용된 데이터 경로가 확보되지 않으면 1~2단계에서 대기한다. 뒤 단계의 설정만 채운다고 네이버 수집 기능이 생기는 것은 아니다.

## 판정과 실패 처리

- 원본 광고 ID가 겹치고 필수 속성이 일치하면 연결한다. 과거에 관측한 ID가 다시 나오면 신규와 구분해 재등장으로 기록한다.
- 기존 엑셀에는 광고 ID가 없다. 이 경우 동·타입·면적·층·방향과 중개소 중복을 보수적으로 비교하고, 후보가 하나일 때만 속성으로 추정해 연결한다. 애매한 경우는 새 추적으로 남기고 ‘동일성 미확인’을 표시한다.
- 같은 출처의 광고 ID가 모두 달라지면 새 광고로 남긴다. 실제 같은 집의 재등록인지 자동으로 확정하지 않는다. 제공처가 검증된 주택 식별자를 제공하면 추후 연결 규칙을 보완할 수 있다.
- 그룹 분할·병합으로 여러 대응이 생기면 임의로 하나를 선택하지 않는다. 신규·소멸 후보 수에는 이런 불확실성이 포함될 수 있다.
- 지속 소멸은 마지막 관측 뒤 정상 조사에서 2회 이상 미관측인 매물이다. 마지막 관측일과 첫 미관측 조사일을 따로 표시한다. 누락된 날짜를 자동으로 미관측 1회로 보간하지 않는다. 재등장 후에는 횟수를 다시 센다.
- 3·7·14일 필터는 마지막 관측 이후 달력상 경과일이다. 매일 정상 수집되었다는 의미는 아니므로 미관측 조사 횟수를 함께 본다.
- 페이지 누락, 총계 불일치, 중복 ID, 형식 오류, 오래된 응답, 원본 ID 누락은 전체 스냅샷을 거절한다.
- 직전 정상 조사보다 대표 매물이 절반 미만으로 감소하면 확인 대상으로 보류한다. 완전한 0건도 자동 소멸 처리하지 않는다. 원본 전체 건수 확인 후 수동 실행에서만 `--accept-count-drop`으로 반영한다.
- 실패하면 이전 매물·이력을 유지하고 `collection-status.json`에 실패 상태만 저장한다. 원본 응답·인증정보·제공처 오류 본문은 공개 상태 파일에 쓰지 않는다.
- 현재 공개 파일은 필요한 숫자·속성·광고 ID·전화번호를 제외한 중개소명만 보존한다. 설명문·연락처·쿠키·인증 토큰은 저장하지 않는다. 공급 계약의 허용 필드에 맞춰 실제 연결 시 다시 검토한다.
- 이력 파일은 임의의 180회 제한으로 잘라내지 않는다. 공급 계약의 보관기간이 결정되면 그에 맞춘 보관·삭제 정책을 설정한다.

## 배포

기본 `GITHUB_TOKEN`으로 데이터 커밋을 푸시하는 것만으로 Pages 빌드가 시작되지 않는 문제를, 갱신 workflow 종료 후 별도의 배포 workflow가 실행되게 해결한다. 배포는 신뢰할 수 있는 `main`만 읽고 공개 허용 목록의 정적 파일만 패키징한다. `incoming`, `config`, `scripts`, 문서, 임시 폴더는 Pages 배포물에 포함하지 않는다. 다만 이 저장소 자체는 공개이므로 비밀자료를 커밋해서는 안 된다.

## 14일 시험에서 확인할 것

실제 시작일은 데이터 이용 확인 후 정한다. 인공 데이터 회귀 검사를 실제 시험 수집 실적으로 기록하지 않는다.

| 점검 | 기준 |
|---|---|
| 최초 수집 | 제공처 전체 총계와 대표·광고 건수 일치, 모든 페이지 확인 |
| 매일 수집 | 예약 시각과 실제 수집 시각 기록, 전체 범위 유지 |
| 정확도 | 최초일, 변동 발생일, 종료일에 표본 광고 ID·금액·층·중복 묶음을 원본과 대조 |
| 변동 | 신규·가격 상하한·월세·소멸·재등장 사례 확인. 실제 발생하지 않은 사례는 별도 시험 데이터로 검증 |
| 장애 | 누락 응답과 인증 실패를 주입했을 때 데이터 유지·실패 표시 확인 |
| 중복 매칭 | 신규/소멸로 잘못 잡힌 광고 교체·그룹 분할 사례를 따로 기록 |
| 최종 판단 | 14일 동안의 정상 수집 비율과 누락 원인, 유지 비용·허용 조건을 보고 운영 여부 결정 |

실거래 신고와 매물은 확정 연결하지 않는다. 매물 소멸은 거래 완료를 의미하지 않는다.
